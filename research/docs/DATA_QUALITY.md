# Data quality

**No real market data has been assessed. Nothing below says anything about MES/ES/NQ data quality.**
The only results shown are from `data/fixtures/SYNTHETIC_*.csv`: seeded random walks generated by
`tradelab.data.synthetic`, used only to test the checking software.

## What is checked (`tradelab.data.quality.quality_report`)

| Check | Severity | Notes |
|---|---|---|
| duplicate timestamps, backwards time steps | error | loader refuses these by default (`validate="raise"`); `scripts/check_data.py` loads with `validate="keep"` so they are reported |
| modal bar step != expected frequency | error | catches a wrong `--freq` or a 5m file labelled 1m |
| OHLC consistency (`high >= max(o,c,l)`, `low <= min(o,c,h)`), NaN, price <= 0, negative volume | error | |
| prices off the tick grid | warn | expected for back-adjusted series (adjustment adds a non-tick offset) |
| zero-volume bars | warn | can be legitimate overnight; count only |
| bars inside nominal closed hours (Fri 17:00 ET -> Sun 18:00 ET, daily 17:00-18:00 ET) | warn | strong sign of wrong timezone or close-vs-open labelling |
| gaps inside nominal open hours | warn | holidays are NOT assumed: gaps on dates in a US-holiday candidate list are tagged `holiday_candidate`, to be verified against the CME calendar |
| Sunday week-open later than 18:00 ET; DST transition dates and their bar counts | warn / info | DST handled via America/New_York; a fixed-offset export shows up as closed-hours bars and late week opens |
| RTH (09:30-16:00 ET) bars per weekday | warn | partial days (early close, outage) and empty weekdays; first and last file dates are excluded as edge days |
| one-bar return spikes (> 10 robust sigma, MAD-based) | warn | only between consecutive bars; review, may be real |
| stale runs (>= 30 identical flat bars) | warn | |
| contract rolls | warn | see below |

The report is a dict (`issues` list with severity/code/message plus detail sections) and
`render_markdown(report)` prints it. Run `python scripts/check_data.py <files> --freq 1min --tz ...`
(exit code 1 on errors).

## DST

Globex is closed across the 02:00 ET clock change (it falls in the weekend closure), so the week opens at
18:00 ET Sunday both before and after: 22:00 UTC in summer time, 23:00 UTC in winter time. Tests
(`tests/test_data_quality.py`) check this for 2024-03-10 and 2024-11-03, that RTH has exactly 390 one-minute
bars on days around each change, that the clean fixtures raise no issues, and that an injected
"fixed-offset export" bug (timestamps shifted 1h after the change) is detected.
Naive local-time exports that fall in the repeated fall-back hour make the loader raise rather than guess.

## Contract rolls (important)

An unadjusted continuous series jumps by the calendar spread (often tens of ES points, ~1%) at each
quarterly roll (H/M/U/Z, third-Friday expiry). That gap is not tradable P&L and a position must not be held across it.

- With a `contract` column: `roll_flags(bars, freq)` marks the first bar after each label change.
- Without one: a heuristic marks gap jumps larger than max(0.3%, 6 robust sigma of all gap jumps) lying within
  12 days before to 2 days after a quarterly third Friday. This only SUSPECTS rolls: it can miss small spreads or
  flag a real news gap. Large gaps with a contract column but no label change are reported separately.
- `drop_roll_sessions(bars, flags)` removes every CME session (18:00 -> 17:00 ET) containing a roll bar plus the
  prior session. The remaining data still has a level shift across the removed days, so any indicator/state that
  carries across days (moving averages, prior-day levels, ATR) must be reset or not span the hole.

Back-adjusted (Panama / ratio) continuous series remove the jump but CHANGE price levels: old prices drift off the
tick grid, can even go negative far back, and anything level-based (prior-day high/low is fine within a day, but
round numbers, absolute distances to old highs, percent moves across the roll) is distorted. Recommendation: use
per-contract data (or unadjusted) and trade only within a contract, with roll-aware day filtering as above.

## Results on synthetic fixtures ONLY (SYNTHETIC, software test, not market data)

`python -m tradelab.data.synthetic` regenerates the three fixtures deterministically (seed 20240101).

- `SYNTHETIC_MES_1m_clean_mar2024.csv` (8340 bars, spans the 2024-03-10 DST change): no issues.
- `SYNTHETIC_MES_1m_clean_fall_dst.csv` (5460 bars, spans 2024-11-03): no issues.
- `SYNTHETIC_MES_1m_defects_mar2024.csv`: injected 5 duplicates, 4 bad OHLC, 6 zero-volume bars, 3 gaps,
  2 spikes, a 40-bar flat run and a 55-point roll. Detected: 5 duplicates, 4 bad OHLC, 6 zero-volume, 3 gaps
  (91 bars missing), 4 spike returns (2 spikes + their reversals), 1 stale run, 1 roll.

## Limits

- The holiday list is a candidate list for flagging, unverified against CME; early-close hours are not modelled.
- Thresholds (10 sigma, 30 flat bars, 0.3% roll jump) are untuned defaults chosen without any real data.
- The synthetic generator has no volatility clustering or realistic microstructure; passing its checks proves little about real feeds.
