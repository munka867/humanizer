# TREND_RESULTS — D4 long-only trend rules (DAILY_SPEC2 v1), TRAIN and VALIDATION only + 5-day forward observation

Status: SEALED test (2025-12-20 onward) was NOT computed. `scripts/run_trend.py` truncates bars at the sealed start before anything is computed, and refuses `--segment test` (exit 2) unconditionally. Nothing was tuned: windows (200; 50/200; 100/50), costs and seeds are exactly DAILY_SPEC2. Tables below are generated by the script (`results/trend/*_report.md`, `verdict.md`, `forward_report.md`) and copied unedited.

Reproduce: `cd research && python -m pytest tests/test_trend_*.py -q && python scripts/run_trend.py --segment train && python scripts/run_trend.py --segment validation && python scripts/run_trend.py --verdict && python scripts/run_trend.py --forward`

## Implementation choices (where the spec was silent)
- Segment evaluation windows: train = eligible dates up to the train/validation boundary (2025-03-04); validation = 2025-03-07 .. 2025-12-19 (the 3-day purge after the boundary is dropped). Daily returns are assigned to segments by date; indicator state is warmed on earlier data only.
- All three ETFs use a COMMON start date per variant and segment (the latest first-eligible date among them, at most a day apart), so the pooled equal-weight series is a plain average on identical dates. B_H buys at that first open (one cost) per ETF. Pooled B_H = equal-weight average of the three ETFs' daily returns (daily-rebalanced).
- Warm-up: first signal at bar index 199 for V1/V2 (200 closes) and 100 for V3 (100 prior closes); the first held day is the next bar. Train therefore starts 2023-08-02 (V1/V2) and 2023-03-10 (V3).
- Max drawdown on the cumulative-return curve starting at equity 1. Annualised volatility = daily sd (ddof 1) x sqrt(252). Round trips = number of sells (closed positions); a position already open at the segment start (carried state) is not counted as a buy.
- Bootstrap: moving-block, blocks 10 (headline CI), 5, 20, 5000 resamples, seed 20261014, percentile CI of the mean daily return difference (strategy - B_H). The Bonferroni column = min(1, 19 x two-sided bootstrap p at block 10); informational only because the rule does not use it.
- B_R: per ETF, permute the strategy's on-run lengths and off-run lengths separately, keep the first state and alternate (same time in market, same switch count). Pooled null = equal-weight average of independently shuffled ETFs. 'pct' counts ties as half; when an ETF has a single run (or the strategy never switches) no shuffling is possible and its pct sits at ~0.5 or is not shown - read the null median next to the observed value.
- Monte Carlo resamples the strategy's own daily returns (moving blocks), 5000 paths, horizon = segment length, seed 20261014. It adds no independent evidence.
- Costs: per buy or sell 1 bp + 0.005/open + 0.35/10,000 of notional (about 1.85 bp at a $100 ETF, ~1.4 bp at SPY ~$500), stress x1/1.5/2. Cash earns 0%; price return only (no dividends, which understates all series, B_H slightly more); taxes and CAD/USD FX not modelled. Costs are tiny relative to the return differences below because there are very few switches.
- Forward observation: dataset B equals A on every overlapping bar (asserted, exact), 5 new bars 2026-10-08..14. Position STATE was computed over the combined series (Donchian is path dependent) - only the last 5 days' returns/positions were computed and printed; no performance for 2025-12-20..2026-10-07 exists anywhere in the outputs. B_H there is price return with no buy cost (held since before).
- Multiple testing: N = 19 registered variants in the project (13 intraday + 3 D3 + 3 D4); the pre-registered decision rule does not use p-values.

## What the sample can and cannot show
- Train (2023-03/08..2025-03-03, ~400-500 days) and validation (200 days, 9.5 months) are each ONE market regime: a rising market with one sharp drawdown (Apr 2025). Round trips per ETF per segment are 0-4. Trade-level inference is meaningless; "per-ETF" and "pooled" numbers come from a handful of regime decisions, and the three ETFs are highly correlated, so pooled is not three independent samples.
- It CAN show the descriptive pattern: how much drawdown each rule would have cut and how much return it gave up in this particular sample. It CANNOT show that any rule has an edge, that it will reduce drawdowns in a future bear market (the sample contains almost none), or that costs/taxes won't matter in other conditions.
- Bootstrap CIs on the mean daily difference vs B_H straddle zero in nearly all rows; the exceptions are D4_V3 on train (underperformance vs B_H, CI excludes 0 on the negative side) and D4_V2 validation SPY/QQQ (slightly negative). No row shows a statistically credible outperformance.
